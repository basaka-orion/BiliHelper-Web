# BiliHelper · 视频学习工作台

把一节视频整理成有依据、可保存、下次能继续用的内容。支持 B 站与 YouTube，一次处理一个视频或一个分 P。

现在有三种整理方式：

- **完整文稿（新导入默认）**：把全篇讲述编辑成连续文章，保留完整例子、推导、论据、命令和限制，只去掉寒暄、广告及纯重复。默认导出纯文稿，也可附原文导出。
- **学习笔记**：原来的全文整理，覆盖当前这一节的全部字幕，按知识与步骤整理成可核对的 Markdown 文档。
- **简短摘要**：保留原来的简明笔记结构（本节目的、关键知识、原文支持的步骤），每次分析一个约 20000 字符的片段。

视频下载是辅助入口：优先由浏览器直接从 B 站 CDN 保存，不再经过服务器中转大文件。

## 完整文档怎么用

1. 打开一节视频，选择「完整文稿」或「学习笔记」。已有文档保留原来的选择，不会自动换模式。
2. 点击对应的生成按钮。程序先读取这一节的全部字幕（来源具备时保留真实时间码），再按约 3500、最多 4500 字符分段，逐段处理。
3. 顶部和底部会显示「第 x/y 段」进度；可以随时停止。已完成的段落会保存，刷新或中断后可点「继续整理」，只处理未完成部分。
4. 完整文稿是标题与连续正文，不套目录、知识点或总结模板；前后段传入有限上下文帮助衔接，合并时不再摘要。学习笔记仍保留目录、知识结构和原文引用。
5. 文稿点击「导出文稿」保存纯文章；需要核对材料时选择「导出文稿（附原文）」。学习笔记的「导出文档（附原文）」保留原有行为。附录只包含实际取得的字幕原文，不伪造时间码。

完整文档以「当前这一节」为单位。多 P 课程每节独立保存；已有笔记的章节可以通过「我的笔记 → 导出这门课程已整理的章节」合并成一个课程 Markdown。

### 完整性与边界

- 完整文档最多处理当前来源的 **240000 字符**；超过时明确报错，不会静默截断。请分段粘贴或改用学习笔记模式逐段整理。
- 完整文稿逐单元核对来源：模型未提出修改的单元直接保留原文，只接受可核验的标点、分段及纯寒暄处理；不同数字或条件的相似案例不能当作重复删除。无法确认的删改会放弃修改并保留原文，代码保持原样；断流或无效响应保留进度供重试。
- 字幕本身是否覆盖整段视频、是否准确反映口述及画面，仍取决于来源。原文可在来源面板核对，选择「附原文」导出可保留底稿；纯文稿导出只包含文章。
- 第 2 P 及以后仍只使用该节的来源：平台字幕、用户粘贴文本，或该分 P 的音频转写；不会改用第 1 P 的内容。

## 学习笔记模式

1. 打开视频后切到「简短摘要」。
2. 检查内容来源，生成「本节目的」「关键知识」及原文支持的操作步骤。非教学内容整理主要内容，不虚构教程。
3. 点击笔记中的「查看原文」核对本次使用的字幕；有真实时间码时可跳转原站回看对应片段。
4. 每次最多分析清洗后的 **20000 字符**；较长内容可在「本次整理范围」选择下一段，实际范围显示在来源中。
5. 重新生成保留上一版；个人备注独立保存，不会被覆盖。

## 本机保存与继续学习

- 笔记、完整文档进度、字幕草稿、个人备注、来源依据及阅读位置自动保存在当前浏览器的 `localStorage`。同一视频的不同分 P 独立保存，切换章节或刷新后可恢复。
- 完整文档进行中会保存已完成的段落、来源和总段数；刷新后标记为未完成，点「继续整理」从下一段开始。
- 重新生成成功后可「查看上一版」并导出；仅保留上一版，不是完整版本历史。停止、超时或中断时保留已收到的内容。
- 「我的笔记」支持搜索、导出、删除和课程合集导出。删除单条后可在当前页面撤销；清除全部本机数据需要确认。
- 保存失败、空间不足或其他标签页发生冲突时会提示，当前修改可能尚未落盘；可重试保存或先导出。不会为腾出空间静默删除已有笔记、输入草稿或备注。
- 暂无账号和跨设备同步。不同浏览器、不同域名分别保存；清理网站数据或关闭无痕会话可能丢失内容。Markdown 导出适合备份，但目前不支持从导出文件恢复整个工作台。
- 本机保存不等于离线生成：获取视频和生成内容需要网络，分析所需内容会经服务端发送至配置的 AI 服务；个人备注不会随生成请求发送。

## 来源、引用与覆盖范围

- 可使用自动提取、平台字幕或手动粘贴的实际字幕。手动文本优先，支持 SRT / VTT，最多 240000 字符；普通文本保留可核对原文，不生成虚构时间码。
- 有原文时，模型按段落编号生成引用。界面仅将本次来源中存在的编号显示为可操作引用；点击可查阅原文。有真实字幕时间码才提供片段回看链接，播放器是否准确跳转取决于原平台。
- 完整文档模式引用全部来源；学习笔记模式引用所选 20000 字符窗口。实际字符范围显示在内容来源中。
- 「已分析取得的全部文本」只表示当前取得的字幕全部进入本次分析，不代表字幕覆盖了整段视频，也不包含对全部视频画面的核验。
- 自动服务只返回摘要、没有可核验原文时，明确标记「覆盖范围未确认」；完整文档模式会拒绝用摘要代替原文，并提示粘贴实际字幕。
- 第 2 P 及以后的分 P 使用该节的平台字幕、用户提供文本或该分 P 的音频转写；缺少来源时引导补充字幕，不将标题或简介当作完整内容。

## 下载

网页下载流程：

1. 服务端用带 B 站 Referer 的官方播放接口取得当前分 P 的签名 MP4 地址（`/api/download` 的 `info` 模式）。
2. 浏览器直接向 CDN 请求文件并显示进度。云端地址和备用线路失败时，尝试为当前分 P 获取浏览器地址；仍失败时，最多 4 MiB 的文件可尝试本站中转，其余使用本机 `yt-dlp`。
3. 浏览器支持文件选择器时在点击后先选择位置，再流式写入磁盘（最多 700 MiB）；否则在内存中组装 Blob 后保存（最多 40 MiB）。取消选择不会自动换方式下载。多片段、需要登录或需要合并音视频的视频仍使用本机下载。
4. 保存前校验 MP4 文件头及完整大小；超限、取消、内容异常或传输不完整时终止，不把失败文件当成成功结果。

这解决了之前「网页下载大一点就中断」的根因：Vercel 等 Serverless 平台对单个函数响应体有约 **4.5 MB** 的上限，而旧实现把最多 40 MiB 的视频完整代理经过函数返回。现在中转路径只保留 4 MiB 以内，超过上限的文件走 CDN 直连。

## 运行与验证

```sh
npm ci
npm run dev
npm test
npm run typecheck
npm run build
```

`npm run dev` 使用 Next.js Turbopack 启动开发服务器；`npm run build` 仍使用默认生产构建。`npm test` 覆盖链接与分 P、代理限制、下载路由的直连/回退、B 站媒体地址、BibiGPT agent 通道请求头、音频转写回退、流式 SSE、SRT / VTT 时间解析、来源分段与引用、完整文档分段与合并、本机保存、版本与中断恢复。模拟请求测试不需要真实密钥，也不调用外部 AI 服务。

## 环境变量

- `BIBIGPT_API_TOKEN`：独立取得视频字幕或音频转录原文。保留在服务端。
- `SILICONFLOW_API_KEY`：分析实际字幕，包括平台字幕、用户粘贴文本，以及自动服务返回的原文，生成带段落引用的内容。
- `SILICONFLOW_MODEL`：可选，默认 `Qwen/Qwen3-8B`。
- `SILICONFLOW_ASR_MODEL`：可选，音频转写模型，默认 `FunAudioLLM/SenseVoiceSmall`；单文件上限按服务方限制为 1 小时 / 50 MB。

生成前会独立刷新浏览器与云端的当前节字幕来源，按字幕语言保留选择，避免长期使用过期字幕地址。手动文本优先，其次读取所选平台字幕；没有有效字幕时，自动模式先通过 BibiGPT 的 `getSubtitle` 取得原文（请求会带官方 agent 通道要求的 `x-client-type: bibi-cli`），再交给字幕分析服务整理。连接失败或服务端错误时，在同一时间预算内尝试官方备用入口，认证、额度与限流错误不会反复请求。

如果 BibiGPT 无法取得原文，或当前是第 2 P 及以后，服务端会下载**当前分 P 的音频流**，用 `SILICONFLOW_ASR_MODEL` 转写后再整理。音频转写不生成时间码，但能覆盖没有平台字幕的视频；仍严格使用请求中携带的当前分 P cid，不会混入第 1 P。

> 请求已按官方接口说明补齐 `x-client-type: bibi-cli`。仅凭 500 状态不能确定上游根因；自动提取失败时会继续尝试当前节音频转写，并保留明确的失败阶段。

完整文档由前端逐段调用 `/api/tutorial`，每次请求只整理一段，避免单个请求超时；每段完成后立即保存。单段请求仍受 165 秒服务端截止时间和 180 秒函数时长约束，但整份文档可以跨请求继续。学习笔记单次生成最长等待 210 秒，始终可停止。

## 功能边界

- 链接解析支持 B 站普通视频页 `/video/BV…`、`/video/av…`、`player.bilibili.com/player.html` 嵌入链接、分享文本、b23 短链接、分 P，以及 YouTube watch、短链接、Shorts、embed、live；链接格式可解析不代表一定能提取内容或下载。番剧、直播、课程、合集、专栏、动态和 UP 主空间不是普通视频页，会给出具体提示；请打开具体视频后复制地址栏中的 `/video/BV…` 链接。
- B 站元数据优先通过云端官方 API 获取，失败时尝试浏览器 JSONP 和视频页面；不依赖第三方 B 站解析站。平台自身的登录、版权、区域和验证限制仍然适用。
- 网页下载仅支持 B 站公开提供的单段 MP4；多片段、需要合并音视频、需要登录、YouTube 和受限视频提供本机 `yt-dlp` 步骤与指令。最高画质合并及音频转换需要 FFmpeg。
- AI 请求支持超时、停止、失败重试。切换到其他已保存章节时，正在运行的生成仍归属于原章节；刷新或关闭页面不会让生成任务在后台继续，但已完成段落会保存。
- 图片和字幕代理只接受指定平台的 HTTPS 资源，不跟随资源重定向。

## 部署

通过仓库的 Vercel 集成部署。`vercel.json` 指定香港区域 `hkg1`；不要将 API 密钥提交进仓库。预览环境需要单独配置 AI 环境变量。预览域名与正式域名的本机笔记分别存储。

部署平台对函数响应体的大小限制（Vercel 常见为 4.5 MB）不会影响 CDN 直连下载；只会让大于 4 MiB 的文件自动跳过本站中转。
