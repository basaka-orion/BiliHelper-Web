# BiliHelper：视频学习工作台首版设计

日期：2026-10-08  
状态：首版设计定案。用户随后授权全面实施；实现已完成，正在验收发布。  
用户已选择：学习笔记工作台；产品取舍交由设计天团负责。

## 1. 产品决定

首版服务正在学习编程、软件操作或其他技能教程的人。他们希望把眼前这一节留下来，下次能找到重点、核对来源、继续照着做。

核心承诺：**把这一节，整理成下次用得上的学习笔记。**

基本工作单位：**一个视频或一个分 P，对应一份可恢复的笔记。** 多 P 课程先选一节；首版不承诺一键整理整套课程。

产品成功的标志是用户留下并再次使用一份有依据的笔记。解析链接、显示封面、生成文字都是为这个结果服务的步骤。

名称暂时保留 BiliHelper，增加中文说明「视频学习笔记」。完成核心体验之后再决定是否改名。

设计参考采用天团的产品主张、可理解性和交互工艺视角。这是项目团队的设计决定，不是对名人意见的转述。

## 2. 首版范围

| 必须做完整 | 作为辅助入口 | 延后 |
| --- | --- | --- |
| 链接导入、当前分 P 识别、课程目录查找 | 保存视频、下载方式与画质 | 整套课程批量整理 |
| 内容读取状态、来源与覆盖范围 | 字幕语言、手动补充字幕 | 跨视频知识库与通用聊天 |
| 生成、停止、重试、保留未完成草稿 | 视频封面、作者、长简介与热度 | 账户、云同步、多人协作 |
| 本机自动保存、刷新恢复、按视频/分 P 找回 | 复制笔记与 Markdown 导出 | 社区、积分、打卡 |
| 个人备注、重新生成时保留上一版 | 有可靠时间信息时的片段跳转 | 无可靠依据的时间点定位 |

个人备注独立于 AI 生成内容保存。重新生成不能覆盖用户写下的内容。

## 3. 页面与阅读顺序

### 首次进入

主标题：「把这一节，整理成下次用得上的笔记。」

说明：「粘贴 B 站或 YouTube 链接，整理要点，留下自己的理解，下次回来继续。」

输入框保留链接、分享文本和 BV 号兼容能力；主按钮叫「打开视频」。它只导入当前对象，不让人误以为点击后已开始 AI 生成。

输入框下放一份明确标注「示例笔记」的真实样例，帮助理解最终成果。样例必须经过来源核对；不把虚构内容包装成真实生成结果。已有笔记的用户优先看到「继续上次」和「我的笔记」，首页品牌展示缩小。

输入错误在输入框附近解释，保留输入文本与正在阅读的旧笔记。一个坏链接不应让工作区消失。

### 桌面工作区

采用两栏：左侧约 240–280px，负责当前视频与课程导航；右侧负责当前这一节的笔记。正文宽度控制在适合中文阅读的范围，避免长句横跨整屏。

阅读顺序：

1. 当前视频和当前节标题，明确「共 200 节，本次为 P2」。
2. 来源条：内容来源、实际覆盖范围、完整性状态。
3. 当前主操作，或已经生成的笔记。
4. 个人备注、复制与导出、下一节。

左侧课程目录可以按节名称查找，分别标记「未整理」「有笔记」「生成中」「未完成」。播放量、点赞量和长简介放入「视频信息」。封面用小缩略图，不继续占据解析后的第一屏。

顶部提供「打开其他视频」「我的笔记」与真实保存状态。打开别的视频是切换文档，不清空此前工作。

### 手机工作区

以单列阅读为主。顶部显示当前节标题，点击「课程目录」打开可搜索的目录；来源详情按需展开。主按钮出现在准备状态的当前屏幕内。

笔记使用页面正常滚动，取消最高 70vh 的内部阅读滚动框。生成状态和停止操作保持容易找到；操作条需避开软键盘和设备安全区。导出、复制等次要操作收进「更多」，减少重复大按钮。

键盘焦点随明确的打开/生成操作进入相应区域，不能随流式文字不断移动。状态通过文字和无障碍播报表达，不只依赖颜色。

## 4. 内容来源决定是否能开始

| 状态 | 页面说明 | 主操作 |
| --- | --- | --- |
| 已取得当前节字幕 | 显示字幕语言、本次实际处理范围 | 生成学习笔记 |
| 当前节可尝试自动提取 | 「将先读取本节内容，取得后再整理」；不提前承诺成功或完整 | 生成学习笔记 |
| 当前节无法自动读取、也没有字幕 | 说明缺少的材料，保留视频信息 | 粘贴字幕 |
| 来源只有部分内容 | 明确本次能处理哪一段；用户知情后开始 | 整理这一段 |
| 已有完整或部分笔记 | 直接展示保存结果与范围 | 继续阅读；重新生成为次要操作 |

只拿到标题和封面不等于拿到视频内容。第 2 P 的来源无法读取时，不能使用第 1 P 代替。当前后端没有对应自动提取能力的分 P，界面不能继续展示一个必然无效的自动操作。

保存状态为「已保存在这台设备」「保存中」「未能保存」；必须依据真实保存结果显示。失败时保留屏幕内容，提供重试保存和导出。

## 5. 笔记的内容结构

顶部保留当前节标题和来源条，正文围绕当前材料实际支持的内容组织：

- **本节要解决什么：** 用简短文字说明内容目的。
- **关键知识：** 保留必要概念、限制和注意点。
- **跟着做：** 仅在教学内容确有步骤时出现；工具、参数、代码和执行顺序必须有来源支持。
- **我的备注：** 用户记录自己的理解、遇到的问题或实际结果，单独自动保存。

课程介绍、音乐或娱乐视频可以生成内容概览，但不显示空的操作步骤，不强行补出教程。重复的「内容概览 / 摘要 / 总结」合并，减少没有新增信息的阅读负担。

补充建议必须与视频原文区分。生成结果不默认宣称用户已经掌握技能；是否学会由用户自己的实践决定。

## 6. 来源条是产品的记忆点

每份笔记都有一条简洁的来源说明，例如：

> P2 · 当前节名称 ｜ 平台字幕 ｜ 已分析取得字幕的全部内容

这是格式示意，具体字段依据真实检测和处理结果填写，不能作为该示例视频的已验证状态。

打开来源详情，可以看到原视频、所用字幕或用户输入，以及覆盖范围。重要要点只有在保留了可靠片段关联时才显示「查看出处」；能核对原文时优先显示原文，能定位视频时间点时再提供跳转。

必须遵守以下表达边界：

- 分析了全部取得的字幕，不等于理解了视频里的全部画面。
- 外部提取服务没有提供可核验范围时，显示「覆盖范围未确认」。
- 当前 60000 字符输入、实际仅分析前 20000 字符的差异，要由产品明确显示；不能只依赖 AI 在文章里自觉声明。
- 首版禁止静默截断。若只能处理一段，生成前明确范围，保留剩余材料；「继续整理剩余内容」依赖真实分段能力，完成之前不显示可执行入口。
- 时间点来自字幕时间码或其他可靠对应关系，不能由 AI 猜测。

## 7. 关键状态与恢复

| 情况 | 设计行为 |
| --- | --- |
| 生成开始 | 在最终阅读位置显示「正在读取内容」「正在整理要点」等真实阶段；不显示虚构进度百分比。 |
| 有文字返回 | 在当前笔记中逐步出现；用户主动向上读时不强行滚到末尾。 |
| 停止 | 保留已返回内容，明确标记「未完成」，允许导出已有内容。 |
| 临时服务失败 | 保留当前草稿与上一版，说明暂不可用，提供重试。 |
| 缺少来源 | 停在来源步骤，提供补充字幕帮助；不让用户反复空等。 |
| 切换分 P | 保存并打开该 P 的笔记和阅读位置；没有笔记的节进入准备状态。 |
| 生成时切换分 P | 首版同时只允许一个生成任务；可以阅读其他已存笔记，顶部明确当前生成的是哪一 P，并提供查看和停止。 |
| 刷新或重新打开 | 恢复保存的笔记、输入草稿、个人备注与当前 P。页面内请求无法确认仍在运行时，标为「上次生成中断」。 |
| 重新生成 | 生成一份新草稿，上一版可查看；失败不能删除上一版。个人备注始终保留。 |
| 删除一份笔记 | 操作明确针对当前笔记，提供撤销；清除全部本机数据需要明确说明范围。 |

本机保存不等于跨设备同步。页面应清楚说明保存位置，提供单篇删除与全部清除入口。

## 8. 下载能力如何保留

下载放在「保存视频」辅助入口中，在用户选择后才展示下载设置。

能网页保存的当前视频才显示网页画质；只支持本机方式的 YouTube 视频展示「在电脑上下载」与适合当前设备的步骤，不再显示无效网页画质选择。40 MiB、工具安装、登录限制在相应路径解释，不提前塞进学习主流程。

首版保留当前下载能力的边界，不承诺通用一键下载。

## 9. 视觉与动效决定

保留现有深色底与紫色强调色，让识别连续。工作区围绕内容阅读调整比例：紧凑标题、清晰段落、少量分隔、明确的当前状态。暖金色只用于适量内容强调，不与主按钮争夺注意力。

减少没有语义的玻璃卡片套层。来源是一条信息条，课程是一个目录，笔记是一份文档；三者的形态直接表达用途。

动效用于切换笔记、展开目录和状态变化；不让用户每次换节都重新观看大幅入场动画。减少动态效果设置应同时覆盖 CSS 和组件动画。

## 10. 交付顺序与验收

第一批优先完成保存、恢复、按视频和分 P 管理状态、保留上一版，确保投入和成果不会因普通操作消失。

第二批完成紧凑工作区、单一生成入口、真实来源状态、覆盖说明与手机阅读。

第三批在可靠来源数据基础上增加片段回看、个人备注与课程导航的细节。时间点定位和后台任务恢复分别需要数据与服务能力，不以界面按钮代替实现。

验收目标如下；这些是设计目标，尚未进行新用户测试：

1. 5 位目标用户中至少 4 位，无讲解完成导入教程、确认当前 P、开始整理，并能说清本次处理哪一节。
2. 使用有字幕、缺字幕、长字幕、外部服务范围未知四类样本，来源、当前 P 与覆盖说明均与实际处理一致。
3. 完成「生成 P1 → 切 P2 → 返回 P1 → 刷新 → 再次生成失败」，笔记和个人备注仍能找回，旧版未被删除。
4. 390px 宽度下能找到当前主操作、生成状态和停止按钮；长笔记只有一个主要阅读滚动层。
5. 重新打开后，至少 4 位目标用户能在 30 秒内找到上次需要的一条内容。

## 11. 本轮证据与验证边界

前轮已现场验证链接解析、P1 笔记生成、切 P 后笔记消失、YouTube 仍显示网页画质，并检查桌面与 390px 手机尺寸的页面。生成结果显示来源，支持复制与导出；源码确认最近记录只保存 URL 和标题。

本文件提出的自动保存、个人备注、目录状态、来源关联和新布局均尚未实施。本轮只产出设计说明，没有改变应用行为，也没有部署。
